# customer-churn-prediction-cloud-deployment

An end-to-end Machine Learning Operations (MLOps) project demonstrating machine learning model development, experiment tracking, model artifact management, testing, Docker containerization, and workflow automation.

## Quick start 

```powershell
python -m pip install -r requirements.txt
python src/train.py
uvicorn src.api:app --host 0.0.0.0 --port 8000
```

Open `http://127.0.0.1:8000/docs` to submit a JSON request to `POST /predict` and use `GET /health` for a service health check. The GitHub Actions workflow runs tests, validates the model against the F1 threshold, and builds the Docker image on every push and pull request. `render.yaml` provides the Docker service configuration for Render.

### API endpoints

| Endpoint | Purpose |
|---|---|
| `GET /health` | Container health check for local runs and Render. |
| `GET /model-info` | Shows the deployed model type, experiment name, and required features. |
| `POST /predict` | Returns a churn prediction and a customer-retention recommendation. |

## Project Overview

This project demonstrates the application of MLOps principles to a machine learning workflow. It organizes the data, model-training code, trained model artifacts, tests, experiment-tracking information, and container configuration into a structured repository.

MLflow is used for experiment tracking where configured. Docker provides a consistent runtime environment, while automated workflows can help validate code and streamline repeatable development tasks.

The project is designed to make machine learning experiments easier to reproduce, evaluate, maintain, and extend.

## Objectives

- Develop and execute a machine learning training pipeline.
- Organize datasets, source code, and model artifacts.
- Track experiments, parameters, metrics, and artifacts using MLflow.
- Evaluate model performance using appropriate metrics.
- Add tests to validate important parts of the application.
- Containerize the application using Docker.
- Automate relevant checks through configured workflows.
- Follow reproducible development and version-control practices.

## Features

- **Machine Learning Pipeline:** Supports model training and evaluation.
- **Experiment Tracking:** Uses MLflow to record experiment information when implemented.
- **Model Artifact Management:** Stores model files and associated outputs.
- **Testing:** Provides a dedicated directory for test cases.
- **Docker Containerization:** Packages the application and required dependencies.
- **Workflow Automation:** Provides a location for automation configuration.
- **Structured Repository:** Separates data, source code, models, and tests.

- `workflows/`: Contains project workflow files or automation-related configuration.

- `.gitignore`: Defines files and directories that Git should ignore.
- `requirements.txt`: Lists the Python dependencies.
- `readme.md`: Provides project documentation.

The local virtual environment, MLflow database, and generated experiment artifacts generally should not be committed to Git unless there is a specific reason to version them.

## MLflow Experiment Tracking

MLflow can record experiment parameters, metrics, and model artifacts to support reproducible experimentation.

### Start the MLflow UI

From the project directory, run:

```powershell

```

Open the following address in your browser:

http://127.0.0.1:5000

If your project uses the local `mlflow.db` database and the `mlruns` artifact directory, make sure the UI is configured to use the appropriate tracking backend and artifact location.

### What to review in MLflow

- Experiment names and run history.
- Model parameters.
- Evaluation metrics.
- Training status.
- Logged artifacts.
- Differences between experiment runs.

The actual information shown depends on what the training script logs.

## Model Artifacts

The `models/` directory is intended to store trained model artifacts if the training pipeline saves them there.

A model artifact may be serialized using a supported library such as Joblib or saved through MLflow.

Before using a saved model, verify:

- The artifact exists.
- The loading code matches the serialization format.
- The training and serving dependencies are compatible.
- The input features match the model's expected schema.
- The model can generate valid predictions.

Do not assume a model file exists until you inspect the directory.

## Docker Setup

Docker provides a consistent environment for running the application.

### 1. Inspect the Dockerfile

```powershell
Get-Content Dockerfile
```

Check that it installs the dependencies, copies the required files, and starts the correct application or script.

### 2. Build the image

From the directory containing the Dockerfile:

```powershell
docker build -t mlops-assignment2:latest .
```

### 3. Run the container

The run command depends on what the Dockerfile starts.

For an API listening on port 8000:

```powershell
docker run --rm -p 8000:8000 mlops-assignment2:latest
```

For a training-only container, run the container according to its configured entry point instead.

### 4. Inspect Docker images

```powershell
docker images
```

### 5. Inspect running containers

```powershell
docker ps
```

A successful image build confirms that Docker could package the configured application; it does not by itself prove that model training, inference, or deployment works correctly.

## Troubleshooting

### Missing Python package

If Python reports `ModuleNotFoundError`, install the project dependencies:

```powershell
pip install -r requirements.txt
```

### MLflow UI does not show the expected experiments

Check the tracking URI, database configuration, and artifact location. Ensure that the UI is reading the same tracking store used by the training script.

### Model artifact not found

Verify that training completed successfully and saved the artifact to the path expected by the loading code.

### Docker build fails

Inspect the Dockerfile and check that all referenced files exist:

```powershell
Get-Content Dockerfile
docker build --no-cache -t mlops-assignment2:latest .
```

### Tests fail

Read the complete test output, confirm the required dependencies are installed, and verify the expected data and model paths.

### Workflow fails

Inspect the failed job logs, identify the first actual error, correct it locally where possible, and rerun the workflow.
